# WebP 转 PNG 功能设计

## 目标

在现有 L-Design 60×60 图片工具中增加显式的 PNG 输出能力。用户上传 PNG、JPG、JPEG 或 WebP 后，可以选择“转换为 PNG”，并下载真实的 PNG 文件。现有的 60×60 输出、10KB 上限和 PNG 去背景能力保持不变。

## 范围

- 输入继续支持单张 PNG、JPG、JPEG 和 WebP 图片。
- 在已有处理选项区增加“转换为 PNG”开关。
- 开启后，输出必须是 `image/png`，下载文件名必须以 `.png` 结尾。
- 输出尺寸固定为 60×60 像素，文件大小严格小于 10KB。
- WebP 中已有的透明区域在转换为 PNG 时保留。
- 去背景功能仍只对 PNG 输入开放，本次不扩展到 WebP 或 JPG。
- 所有处理继续在浏览器本地完成，不上传用户图片。

不包含原尺寸 PNG 转换、批量转换、动画 WebP 帧保留或服务端压缩。

## 交互设计

“转换为 PNG”与现有去背景控制放在同一处理选项区域，使用现有开关样式和 `#FFDB00` 选中态，不改变页面的整体布局与视觉方向。

用户上传图片后默认维持当前的自动格式策略，以最大概率满足 10KB 限制。开启“转换为 PNG”后立即重新处理，并在结果区域明确显示格式为 PNG。下载按钮沿用现有位置，生成 `<原文件名>-60x60.png`。

PNG 输入也可以开启该选项；此时作用是保证输出格式为 PNG。PNG 输入的去背景开关可与“转换为 PNG”同时使用。

## 处理架构与数据流

界面组件维护一个布尔状态 `forcePng`，并与 `removeBackground`、`tolerance` 一起传给图片处理模块。图片处理模块负责解码、可选去背景、等比缩放并居中到 60×60 画布，然后根据输出模式选择编码候选：

- `forcePng = false`：沿用当前 PNG、WebP、JPG 自动候选策略。
- `forcePng = true`：只尝试 `image/png`，不得回退到 WebP 或 JPG。

处理结果继续返回 Blob URL、尺寸、MIME 类型、字节数和背景识别置信度。界面根据返回的 MIME 类型显示格式，并使用同一类型生成下载文件扩展名。

## 错误处理

- 不支持的格式继续在解码前拦截并显示现有提示。
- 图片损坏或浏览器无法解码时显示可理解的读取失败提示。
- 强制 PNG 后若文件无法小于 10KB，显示“无法将这张图片以 PNG 格式压缩到 10KB 以下。”，不生成错误格式的下载文件。
- 处理选项变化引起的新请求继续使用现有序列控制，过期结果不得覆盖最新结果。

## 测试与验收

自动化测试覆盖：

- WebP 仍通过输入格式校验。
- 自动模式保留现有编码候选顺序。
- 强制 PNG 模式只返回 PNG 编码候选。
- 强制 PNG 的下载文件名以 `.png` 结尾。
- PNG 超过 10KB 时返回专用错误信息。
- WebP 透明像素转换后仍具有透明通道。
- 现有去背景、尺寸计算和状态辅助测试继续通过。

浏览器验收使用至少一张 WebP 图片：上传后开启“转换为 PNG”，确认结果为 60×60、格式显示 PNG、文件小于 10KB且下载文件可正常打开。另使用透明 WebP 验证透明区域未被白色填充。

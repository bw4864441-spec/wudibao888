# L-Design 60×60 图片压缩与去背景工具设计

## 目标

构建并公开发布一个无需登录的单页图片工具。用户拖入或选择一张图片后，工具在浏览器本地将图片生成成 60×60 像素，并把下载文件控制在 10KB 以下。PNG 图片可以移除纯色或近纯色背景。

## 范围

### 包含

- 接受 PNG、JPG、JPEG 和 WebP 图片。
- 支持点击选择和拖拽上传。
- 默认保持原图比例，以 `contain` 方式居中放入 60×60 画布，不拉伸、不裁切主体。
- PNG 图片提供去背景开关和容差调节。
- 自动推断四角的主要背景色，移除与背景色接近且从画布边缘连通的像素。
- 对抠图边缘应用轻微透明过渡，减少锯齿和白边。
- 自动选择可满足体积要求的输出编码和质量。
- 显示原图、结果预览、原始尺寸、输出尺寸、原始体积、输出体积和输出格式。
- 支持下载生成图片。
- 所有处理都在浏览器本地完成，不上传、不存储图片。
- 响应式支持桌面与移动设备。

### 不包含

- 人像、毛发或复杂场景的 AI 语义抠图。
- 批量处理。
- 用户账户、历史记录或云端文件存储。
- 手工涂抹式蒙版编辑器。

## 视觉与页面结构

页面使用 L-Design 品牌语言：黑白高对比界面，`#FFDB00` 用于主操作和选中状态。`public/assets/brand/lbank-design-logo.png` 只显示在圆形品牌标记内，旁边单独排版 `L-Design` 名称。

首屏结构如下：

1. 顶部品牌栏，包含圆形标记、`L-Design` 名称和“图片工具”说明。
2. 左侧或上方为上传区，展示“拖入图片，生成 60×60 / 小于 10KB”的核心承诺。
3. 上传后进入双栏工作区：左侧原图，右侧结果。
4. PNG 的结果区显示去背景开关与容差滑杆；非 PNG 显示说明而不展示无效控件。
5. 结果卡显示透明棋盘格、尺寸、格式和体积状态。
6. `下载图片` 为黄色主按钮，`重新选择` 为次级操作。
7. 页面底部用短文案说明“图片仅在你的浏览器内处理”。

## 图片处理流程

### 读取与校验

1. 校验 MIME 类型是否为 PNG、JPEG 或 WebP。
2. 解码为浏览器位图；解码失败时显示明确错误并允许重选。
3. 释放旧的 Object URL 和位图资源，避免连续处理造成内存泄漏。

### 去背景

去背景仅对 PNG 开放，且默认关闭：

1. 从原图四角的小块区域采样颜色，选择出现频率最高且相互接近的颜色作为背景候选。
2. 以用户容差计算每个像素与背景色的颜色距离。
3. 从图片边缘执行连通区域搜索，只清除与边缘连通的背景像素，避免误删主体内部的同色区域。
4. 接近阈值边缘的像素按距离映射为部分透明，形成轻微羽化。
5. 改变开关或容差后重新生成结果。

如果四角颜色差异过大，仍允许用户尝试，但显示“背景可能不够统一”的非阻断提示。

### 60×60 生成

1. 使用 60×60 的 Canvas 作为目标画布。
2. 按原始宽高比计算 `contain` 尺寸并居中绘制。
3. 透明输出使用透明画布；不透明格式使用白色画布。
4. 使用高质量缩放设置，并在必要时采用分步缩小，减少一次性大幅缩放造成的混叠。

### 小于 10KB 的保证

编码器按透明性选择策略：

- 有透明像素：先尝试 PNG；超过限制时尝试 WebP 并递减质量。
- 无透明像素：比较 PNG 与 WebP；必要时尝试 JPEG 并递减质量。
- 每次编码都检查 Blob 实际字节数，只有小于 10,240 字节才标记成功并开放下载。

由于输出只有 60×60 像素，常规图片预计都可满足限制。如果浏览器不支持所需编码或极端内容仍无法满足，工具不提供超限下载，并显示失败原因和可重试建议。

## 组件与代码边界

- `Prototype`：页面布局和整体交互状态。
- `ImageDropzone`：文件选择、拖拽和格式提示。
- `ImagePreview`：原图与结果棋盘格预览。
- `BackgroundControls`：PNG 去背景开关与容差。
- `ResultSummary`：尺寸、格式、体积和状态。
- 图片处理模块：文件校验、背景采样、连通区域清除、缩放和编码。该模块不依赖 React，便于单元测试。

现有 Sites 构建与托管文件保持不变。现有未提交的图标数据修改不属于本功能，不改动也不纳入本功能提交。

## 错误和状态

- 未选择图片：显示上传引导。
- 不支持的格式：提示仅支持 PNG、JPG、JPEG、WebP。
- 解码失败：提示文件可能损坏。
- 处理中：禁用下载并显示简短进度状态。
- 背景不统一：非阻断警告，允许调整容差。
- 无法达到 10KB：阻断下载并建议更换图片或关闭透明背景。
- 成功：明确显示 `60×60`、实际格式和小于 10KB 的体积。

## 可访问性与交互

- 上传区域可通过键盘聚焦并用 Enter 或 Space 打开文件选择器。
- 所有按钮、开关和滑杆都有可读标签与焦点状态。
- 结果不只依赖颜色表达，体积状态同时显示文字和数值。
- 拖拽不是唯一输入方式。
- 移动端按钮保持足够触控面积。

## 验收标准

1. 拖入支持格式的图片后可获得 60×60 结果。
2. 下载文件的实际体积小于 10,240 字节。
3. 原图不被拉伸，主体完整居中。
4. PNG 可开启去背景并调节容差，纯色背景可变透明。
5. 非 PNG 不显示可执行的去背景控制。
6. 页面清楚展示输入与输出信息。
7. 图片不发送到服务器；实现中不存在图片上传请求。
8. 错误文件和不支持格式不会导致页面崩溃。
9. 桌面和移动端均可完成上传、预览与下载。
10. `npm run build`、项目测试和 `npm run test:sites` 全部通过，Sites 构建产物完整。
11. 完成后发布为可公开访问的网站。

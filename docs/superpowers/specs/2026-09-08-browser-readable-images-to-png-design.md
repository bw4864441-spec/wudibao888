# 浏览器可读图片转 PNG 设计

## 目标

扩展现有 60×60 图片处理工具，使用户可以上传浏览器能够解码的常见位图格式，并转换为真实 PNG 文件。输出继续保持 60×60 像素，并严格小于 10KB。

## 范围

支持 PNG、JPG/JPEG、WebP、GIF、BMP、AVIF 和 ICO 等常见位图格式。最终能否处理以当前浏览器的实际解码能力为准。

SVG、HEIC/HEIF、TIFF 和相机 RAW 不在本次范围内：SVG 不是位图且可能包含外部资源，其他格式通常需要额外解码库，不能保证浏览器原生支持。

GIF 或其他动态图只读取首帧，并将首帧转换为静态 PNG。

## 上传与校验

- 文件选择器接受 `image/*`，并补充 `.png,.jpg,.jpeg,.webp,.gif,.bmp,.avif,.ico` 扩展名提示。
- MIME 类型匹配 PNG、JPEG、WebP、GIF、BMP、AVIF 或 ICO 的文件可以进入解码流程；SVG、HEIC/HEIF、TIFF 和 RAW 明确拒绝。
- 某些系统上传文件时可能没有 MIME 类型；若扩展名属于上述常见位图格式，允许进入解码流程。
- 其他文件在解码前拒绝，避免把任意文件交给图片处理流程。
- 解码结果是最终判断标准。浏览器无法读取时显示：`当前浏览器无法读取此图片格式，请换用 PNG、JPG、WebP、GIF、BMP 或 AVIF。`

## 解码架构

新增统一的图片解码层，向后续画布流程返回可绘制对象、原始宽高和清理方法：

1. 优先调用 `createImageBitmap(file)`，延续当前性能较好的处理路径。
2. 如果失败，则创建临时 Object URL，并使用 `HTMLImageElement` 的 `decode()` 或 `load` 事件尝试浏览器展示层的兼容解码。
3. 两条路径都失败时，抛出统一的浏览器不支持提示。
4. 无论成功或失败，都必须关闭 ImageBitmap（如适用）并撤销 Object URL，避免内存泄漏。

解码层与压缩层分离，以便测试首选路径、回退路径和双重失败路径。

## 转换与压缩

- 沿用现有居中裁切和 Canvas 绘制逻辑，生成 60×60 输出。
- 保留透明通道，不主动填充白色背景。
- 保留“转换为 PNG”开关；每次接受新图片后默认开启，使上传后的主流程直接得到 PNG。用户仍可关闭它，使用现有自动压缩行为。
- 开关开启时只选择 PNG 编码候选，不允许用 JPG/WebP 内容冒充 `.png`。
- PNG 输出必须小于 10KB；无法满足时沿用现有失败提示，不返回超出限制的文件。
- 去背景能力仍只对原始 PNG 输入开放，避免改变现有产品边界。

## 界面调整

不改变现有页面布局，只更新上传能力说明：

- 上传提示改为：`PNG / JPG / WebP / GIF / BMP / AVIF / ICO · 单张图片`
- 上传成功后继续展示原图格式、尺寸、处理状态和下载按钮。
- PNG 转换开关默认开启，并允许用户手动关闭。

## 错误处理

- 非图片文件：在进入解码前提示选择受支持的图片文件。
- SVG：明确提示当前仅支持常见位图格式。
- 浏览器无法解码：使用统一兼容性提示，不暴露底层异常。
- 图片解码成功但 PNG 无法压到 10KB 以下：使用现有体积限制提示。
- 任一失败路径都清理临时对象，并保持界面可重新上传。

## 测试与验收

自动化测试覆盖：

- 接受 `image/gif`、`image/bmp`、`image/avif`、`image/x-icon`。
- MIME 为空但扩展名为常见位图格式时允许尝试解码。
- 拒绝文本文件和 SVG。
- `createImageBitmap` 成功时使用首选路径。
- `createImageBitmap` 失败时使用 HTMLImageElement 回退路径。
- 两种解码方式都失败时返回约定的中文提示。
- 开启 PNG 转换后输出 MIME 为 `image/png`、文件名以 `.png` 结尾、尺寸为 60×60，且体积小于 10KB。
- 去背景开关仍只对原始 PNG 文件可用。

浏览器验收覆盖 PNG、JPG、WebP、GIF、BMP，以及环境支持时的 AVIF/ICO；验证 GIF 只输出首帧、透明背景保留、下载文件可正常打开。
